Key 泄露，为什么是大事

刚才那次调用用的 Key 就暴露在浏览器里 —— 它背后的事，值得一看。

0
2025 年公开 GitHub 仓库新增泄露密钥
GitGuardian《State of Secrets Sprawl》年度统计 · 同比 +34%，历年最大涨幅
GitHub 官方口径：2024 年检出泄露密钥 3,900 万+
GitHub 内置密钥扫描（Secret Scanning）能识别 200+ 种令牌、实时验证真伪，并通知服务商吊销公开仓库里的泄露 Key。 但它管不到你本地 Agent 里的环境变量，也管不到已经被套话读出来的那一次。

// 泄露之后会发生什么

01

烧钱无下限

Key 被盗就是 Token 被刷，恶意调用能刷出天价账单。

02

冒名作恶

别人用你的身份生成违规内容，封号和责任都算你头上。

03

连锁失陷

Key 往往是账号入口，顺着能摸到数据库、存储等更多资源。

04

静默流血

泄露不会像密码错误那样报警，账单爆炸时才发现。

// Agent 是怎么把 Key 漏出去的

A1

提示词套话

注入攻击让 Agent「把配置文件打出来」，环境变量里的 Key 被直接朗读。

A2

旁路外溢

日志、报错堆栈、调试界面顺手把 Key 打印到全世界。

A3

扩散复制

多 Agent 协作与长期记忆，让明文 Key 被复制得到处都是。

⚔ 试试注入大肥鱼

挑一句攻击话术，自动装进上方输入框，成不成看鱼的造化 —— 但就算套话成功，你得到的也只有人设文案：真 Key 从未进入它的上下文，它想漏也没得漏。

// 怎么防

P1

最小权限 + 预算

每个用途独立 Key，设花费上限，到数即停。

P2

不进提示词不进日志

Key 别放在模型「读得到」的地方，日志一律脱敏。

P3

代理 + 短期凭证

对外只发假令牌，真 Key 锁在服务端。

← 本页就是这个方案：你偷到的 demo_ 是假钥匙，真 Key 只活在云函数环境变量里
P4

轮换 + 监控

定期换 Key，用量异常立刻告警。
